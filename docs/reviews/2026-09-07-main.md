## Summary
This changeset establishes the design system foundation for Velocast by harmonizing Tailwind CSS v4 tokens, refining Base UI primitives with stadium geometry, enhancing theme switching across cookies and local storage, and implementing responsive dashboard navigation with fluid motion tabs. Overall quality is high with clean component structure, zero flash theme execution, and full compliance with Biome rules. One major mobile viewport interaction defect requires attention before merge: the fixed header logo collides with the sticky mobile navigation drawer button during scrolling.

## Major
### 🟠 Fixed header logo overlaps mobile navigation on scroll, `src/features/dashboard/components/header.tsx:113`
**Problem**: The Velocast logo in AnimatedHeader is positioned with fixed top-0 left-0 z-50. On desktop screens, tabsShiftX shifts the tabs horizontally on scroll to make room for the fixed mark. On mobile viewports, tabsShiftX is not applied, and MobileNav renders a full width accordion button inside px-4. When a mobile user scrolls down and the sticky navbar docks at top-0, the fixed logo floats directly over the left label text of the mobile accordion button and intercepts touch events.
**Why it matters**: Mobile users scrolling past the top hero cannot reliably tap the mobile navigation trigger because taps on the left side hit the fixed dashboard logo link instead, preventing navigation drawer expansion and causing visual clutter.
**Suggested fix**: Make the logo flow naturally with the top bar instead of remaining fixed, or hide the fixed logo during mobile scroll, or nest the logo inside the sticky container alongside the mobile toggle.

## Minor
### 🟡 Missing aria-current on active dashboard navigation links, `src/features/dashboard/components/tabs.tsx:112`
**Problem**: Neither DesktopTabItem nor MobileNav applies aria-current="page" to the active route link.
**Why it matters**: Screen readers have no semantic signal indicating which navigation item represents the currently active view, relying purely on visual styling like font weight and pill backgrounds.
**Suggested fix**: Add aria-current={isActive ? "page" : undefined} to the Link components in both DesktopTabItem and MobileNav.

### 🟡 Redundant theme script element rendered inside body, `src/providers/theme.tsx:132`
**Problem**: The themeScript is rendered via ScriptOnce inside head in src/routes/__root.tsx, but ThemeProvider in src/providers/theme.tsx also retains a duplicate ScriptOnce invocation inside body.
**Why it matters**: This duplicates inline script execution during server rendering and hydration, placing an unnecessary script tag in the body DOM when the head tag already executes before paint.
**Suggested fix**: Remove the duplicate ScriptOnce tag from ThemeProvider in src/providers/theme.tsx and rely solely on the root head placement.

### 🟡 Mobile navigation drawer does not close on external route changes, `src/features/dashboard/components/tabs.tsx:41`
**Problem**: The mobile navigation drawer open state is toggled manually and closes on item click, but does not reset when the route pathname changes through external navigation such as browser history traversal.
**Why it matters**: If a mobile user opens the drawer and navigates backward using the browser back button, the drawer stays open over the prior screen.
**Suggested fix**: Add an effect watching the pathname from useRouterState that sets open to false whenever the route changes.
